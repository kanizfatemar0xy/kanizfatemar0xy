# London Weather Data Science Project — Repair and Test Report

**Reviewed input:** User-supplied `DataScienceReport.ipynb` (33 cells, approximately 1.8 MB, with old chart outputs)  
**Revised notebook:** `DataScienceReport_Fixed.ipynb` (22 cells; 11 executable code cells)  
**Scope:** Weather data quality, descriptive analysis, time-series model evaluation, reproducibility, and GitHub publication readiness.

## Confirmed original issues and corrections

| Finding in source notebook | Correction |
| --- | --- |
| Mounted a personal Google Drive path and assumed an unavailable CSV | A documented downloader caches the public original CSV in `data/`; offline use is supported with a manually saved source CSV |
| Divided temperature, sunshine and precipitation by 10 in multiple cells (6, 11, 19) | A single audited cleaning function divides TX/TN/TG/SS/RR/PP by 10 **once**; all other units retain their correct source scale |
| Inconsistent datetime conversions (including parsing timestamps as YYYYMMDD again) | Source dates are parsed *once* using `%Y%m%d`, checked for invalid and duplicate dates, and sorted |
| Ignored measurement quality codes and replaced all missing values with global medians | Only `Q_<variable> == 0` readings are used; suspect and missing values remain missing for plots; 90% monthly/annual completeness requirement prevents misleading totals |
| Repeated annual rainfall charts and overlapping analyses | Notebook sections consolidate the original descriptive RQs with distinct, labelled graphs |
| Forecast code mixed same-day weather with predictors, risking unavailable-future-information leakage | New `next_day_frame` uses day `t−1` lags and earlier rolling windows for a target on day `t`; daylight-season features are calendar-known |
| Mixed random splitting and non-temporal CV (cells 27, 29, 31) | Training 1979–2018, validation 2019–2020, held-out test 2021–2023; models selected by validation MAE |
| Scalers and imputers could fit on holdout observations | All feature imputers and scalers are inside scikit-learn pipelines fitted on training data; refit uses train + validation only after selection |
| No non-ML forecast comparison | Persistence and training-only monthly climatology baselines are included |
| Original notebook retained potentially invalid chart outputs | All published notebook code cells start with **empty outputs**; graphs/results are regenerated when the authentic data are available |
| Missing installation and reproducibility instructions | Added README, requirements, data provenance, GitHub Actions unit tests and a complete synthetic-data notebook execution test |

## Public dataset verified independently

A live read of the publicly hosted CSV confirmed **16,436 daily rows, 21 columns**, from **1979-01-01 to 2023-12-31**, with **no duplicate date keys**. The upstream dataset README describes station ID 1860 near Heathrow and the ECA&D unit definitions.

Source quality flags include `Q_TG=1` on **1,119** days and `Q_TG=9` on **29** days. These readings must not be treated as automatically valid or median-filled in historical plots. For comparison `Q_RR=0` on all 16,436 rows in this mirror. These counts are **source-file inspections**, not output from running the corrected notebook locally on the complete public dataset.

Data: https://github.com/pc1991/London-Weather-Data-From-1979-To-2023

## Automated test evidence

Run from project root:

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

**Result: 18 tests passed.** These test parsing and conversion, flag filtering, missingness, source validation, monthly/annual coverage, leap years, decadal and rainfall summaries, future-information exclusion, missing calendar dates, chronological partition boundaries, regression metric handling, both modelling code paths, notebook syntax, and publication-output hygiene.

Additional executable integration test:

```bash
python tests/run_notebook_smoke.py
```

**Result: 22 notebook cells (11 executable code cells) completed without errors** on an **explicitly SYNTHETIC** 16,436-row source-format fixture with the same date range. Synthetic results are discarded; the project distribution contains **no synthetic outputs or substitute weather dataset**.

## What has NOT been proven

- **The full real-data notebook has not been run in this environment:** the complete source CSV could be read through the public repository integration, but the local execution container had no external network access to download it as a file. The notebook's real-data metrics and plots must be generated by running the provided code with the authentic CSV.
- All source quality and completeness choices are stated, but a formal climate homogeneity assessment, trend significance test and attribution analysis were not performed.
- Model output is not an independently validated operational forecast; baseline comparisons and held-out metrics should be interpreted as historical backtests only.
- An automated notebook test with synthetic data does not establish the accuracy of the real-data historical findings.
- The notebook and source code are **prepared for a new GitHub project** but **have not been uploaded** to the user's GitHub account as part of this repair.
